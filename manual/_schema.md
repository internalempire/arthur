# Schema

> The conventions every page in this manual follows, and why each one exists. This file is for whoever writes the next page — a person or a language model. Readers want [conventions](conventions.md) instead.

---

## The three layers

The manual is deliberately not the only place knowledge lives.

| layer | where | what it is |
|---|---|---|
| sources | `docs/` | Immutable record: `MODEL_DECISIONS.md`, `LITERATURE_RANGES.md`, `PHYSIOLOGY.md`, the audits and postmortems. Written when a decision was taken. |
| the wiki | `manual/*.md` | These pages. Written for a reader, cross-linked, rewritten freely. |
| schema | this file | The conventions. |

Work identified but not done is recorded in [`_todo.md`](_todo.md), so an acknowledged gap is not mistaken for an oversight.

A page never restates a source at length. It explains, then links. Files under `docs/` record why a decision was taken, but they can become stale after code changes or later physiological review. When sources, manual and implementation disagree, the discrepancy must be resolved explicitly rather than assigning automatic priority to any one layer.

## What every page contains

```
# Title
> One sentence of summary. This is what appears in manifest.json and _index.md.

## Physiology            always — brief where the concept is ordinary, developed where it is not
## In the model          only where the implementation is itself content
## Why this and not something else    the alternative that was rejected, and on what grounds
## Limits                of construction and of clinical application — always
## Validation            the executable rows that constrain this page, where any exist
## References            design sources plus a literature search
## See also              three to six lateral links
```

`In the model` is not a code tour. Compliance does not need explaining; the recruitment-to-inflation solver and the pulmonary transit stages do. The test is whether a reader could be misled about what the number means without it.

`Limits` is the section that must never be thin. Both halves are required: what the construction cannot represent, and what a clinician must not conclude from it.

## Rules

**Write in English.** The repository is in English, and these pages sit beside sources that are.

**Call it "the model".** The name `arthur` belongs on the home page, in the title bar and where the application as a product is being discussed. In the body of a physiological explanation the subject is "the model", "the simulator", or nothing at all. A concept page is about the physiology first.

**Write for a clinician before writing for an implementer.** State the bedside meaning in ordinary physiological language first. Give equations only when they prevent ambiguity or reveal an important limitation, and define implementation terms immediately if they cannot be avoided. Phrases such as “distribution midpoint”, “algebraic component”, “stateful fraction” or “play operator” must never carry the explanation by themselves.

**Prefer a literal statement to an elegant abstraction.** Name what the reader would actually see: “the points fall approximately on the same curve” is clearer than “the limbs approach one relation”. Preserve uncertainty with ordinary qualifiers such as “approximately” or “in this preparation”, not with abstract wording that the reader must translate before understanding the physiology.

**Display-math delimiters sit alone on their own line.** Renderers disagree about `$$formula$$`. One that shared a line closed nothing, and the maths swallowed the paragraph after it. The manual's own renderer accepts both forms; the linter accepts one.

**One line per paragraph.** Hard-wrapped prose keeps the author's line endings in any renderer that treats a newline as a break, and the paragraph stops reflowing. Wrapping is for code, not for pages.

**Every symbol in a formula is defined immediately under it.** A definition list naming each symbol, what it is, and its units. A reader who knows the physiology should never have to infer from context that $P$ is a pressure and $E$ an elastance — and a reader who does not know it cannot. Where a symbol is a control, name the control. Where it is a fixed coefficient, give its value and say what it does.

**Every model number comes from the code, never from memory.** Quote what the model actually produces, obtained by running it. Figures generated by `manual/figure/generate.mjs` should use the same functions as the model so their numerical behaviour does not drift. Shared code guarantees fidelity to the implementation, not physiological validity or a correct interpretation of the axes.

**A coefficient chosen to express an unquantified principle carries no citation.** Where a constant was picked to make a well-established but never-measured relationship visible, the page calls it a **didactic shape coefficient** and names no paper. Attaching a citation to a chosen number misrepresents both. Where a constant *is* anchored, the page says to what, and under which measurement conditions.

**State reversals.** Where the model once did something else, say so and say why it changed. Several of this model's most defensible positions are reversals, and a reader who only sees the conclusion cannot judge it.

**Link liberally, including to pages that do not exist.** A link to an unwritten page renders as a placeholder that names the gap. That is the point: it marks work to do rather than hiding it.

## Adding a page

1. Add one line to `manifest.json` in the right section: `["slug", "one-line summary"]`.
2. Write `manual/slug.md`.
3. `npm run manual:build` — regenerates `status.json` and `_index.md`.
4. `npm run manual:lint` — must exit clean.
5. Append a line to `_log.md`.

No HTML is generated per page. The viewer fetches markdown and renders it, so a new page is one markdown file and one manifest line.

## Lint

`npm run manual:lint` renders every page through `render.mjs` — the same module the browser loads — and reports:

- maths that fails to compile, and any `$` surviving into the rendered text
- display delimiters not alone on their line; a block never closed
- hard-wrapped paragraphs
- links to slugs absent from the manifest, missing assets, broken paths out of the manual
- pages present but unlisted, so nothing links to them

It exists because the two formatting defects that shipped were both invisible to a checker that read the source: the files were internally consistent and still wrong. Anything a reader would see broken should be something this catches.

What it cannot check is whether a page is *true*. Contradictions between pages, claims gone stale after a change to the model, and numbers that were right last month remain a human reading.
