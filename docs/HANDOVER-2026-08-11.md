## 2. Agreed product and development constraints

These constraints come from explicit discussion with the project owner and
should be treated as requirements.

### Teaching scope

- The central subject is **mechanical heart–lung interaction**, not exhaustive
  respiratory physiology or exact reproduction of a human patient.
- Prefer a small mechanism that teaches a causal relation over a detailed model
  with many poorly identifiable variables.
- Numerical outputs should be plausible, but the application must not imply
  patient-specific prediction or bedside treatment guidance.
- A mechanism omitted for clarity must be documented as an interpretability
  limit, especially when a clinical scenario would normally depend on it.
- It remains useful to separate a compound ARDS phenotype from an isolated
  compliance change. The latter is clinically artificial but didactically
  valuable because it isolates one causal variable. Do not collapse those two
  experiments into one preset or interpretation.

### Technical scope

- Preserve the vanilla JavaScript architecture unless a concrete limitation
  cannot be solved reasonably within it.
- Do not add a Python or Node application framework. Node may continue to run
  tests and development tools.
- Keep browser-facing model imports behind `src/model/index.js`.
- All substantive changes must be commented or recorded in
  `docs/MODEL_DECISIONS.md` so another developer or model can reconstruct the
  rationale.
- Every change must be versioned with Git. Work on a `codex/…` branch, run the
  relevant checks, commit, push, and open or update a pull request.
- Pull requests are created automatically as part of completed work. Merging is
  a distinct operation and should occur only when requested or approved.
- Never hide a test failure behind a shell pipeline. The historical postmortem
  records a commit that landed because `test | tail` returned the status of
  `tail`, not the test process.

### Documentation scope

- A true multi-page, hypertextual manual is planned after structural closure.
- The manual must cover code, model architecture, physiology, scenarios,
  literature and limitations, not merely reproduce control labels.
- Scenario limitations must be analysed globally, distinguishing what the model
  generates from what each preset encodes as a starting phenotype.
- Existing dated audits and postmortems are historical evidence, not necessarily
  descriptions of the current implementation.

## 5. Current architecture

### Runtime data flow

```text
parameter/scenario selection
        ↓
Simulator.params
        ↓
respiratory state + circulation state + baroreflex
        ↓
fixed-step closed-loop integration
        ↓
cycle/breath measurements and interpretability flags
        ↓
stats, textual descriptions and six visual panels
```

The panels should present model state, not reproduce competing physiology in the
UI. Shared analytical constructions that must agree with the integrator belong
in the model and are exported selectively through `src/model/index.js`.

### Main modules

- `src/main.js` — application wiring, scenario selection, transport, animation
  invalidation and the scripting handle `window.heartLung`.
- `src/model/simulator.js` — owns the live state, advances the model, records
  breath/cycle metrics and exposes derived measurements.
- `src/model/circulation.js` — closed circulation, ventricular interaction,
  venous return, pulmonary transit and analytical cardiovascular curves.
- `src/model/respiratory.js` — equation of motion, ventilatory modes, holds and
  expiratory flow limitation.
- `src/model/lung.js` — lung volume/pressure relation, recruitment, hysteresis,
  R/I calibration, lung regions and PVR components.
- `src/model/baroreflex.js` — one bounded aggregate compensator.
- `src/model/parameters.js` — single catalogue of all user-facing controls.
- `src/model/scenarios.js` — twelve partial parameter overrides and their
  intended teaching questions.
- `src/model/index.js` — stable public browser-facing model API.
- `src/ui/descriptions.js` — text equivalents and openable value tables for the
  canvas panels.
- `src/ui/plot.js` — shared canvas primitives and scale handling.
- `tests/suites/` — safety, core physiology, regulation/transit, circulation,
  lung mechanics, recruitment and cross-layer contracts.

The largest model files are currently `lung.js`, `circulation.js` and
`simulator.js`. Their size alone is not a reason to split them. Refactor only
around a coherent domain boundary and preserve the public API plus behavioural
tests before moving code.

## 6. Physiological model: current meaning

### Pulmonary vascular resistance

- The didactic mechanical PVR construction is the series sum of an alveolar
  limb that rises with lung volume and an extra-alveolar limb that falls as
  radial traction opens vessels.
- The two limbs cross near the fully open vascular FRC. The total is a classical
  J-curve with both low- and high-volume limbs visible.
- The graph always retains the complete RV–FRC–TLC x-axis. Its vertical zoom
  levels are Fit, 150%, 200% and 300%, initially centred on the live patient
  value. Zoom is view-only and does not mutate model state.
- The mechanical model coefficient and catheter-derived
  `(mPAP − wedge) / CO` are separate readouts. Neither should be called a pure
  Poiseuille resistance.
- Collapse, open/closed vascular pathways, HPV and the alveolar waterfall alter
  the live patient point but are not drawn as extra limbs of the classical
  construction.
- Acute pulmonary embolism is a raised **aggregate effective pulmonary vascular
  load**. There is no anatomical clot burden or separate obstruction pressure.

### Volume and venous return

- `stressedVolume` adds or removes actual blood above the systemic venous
  zero-pressure volume.
- Venous tone shifts up to 200 mL from unstressed to stressed volume without
  changing total blood volume or compliance.
- Venous compliance is the slope converting stressed volume into pressure; it
  is not a synonym for stressed volume.
- Abdominal coupling can raise mean systemic filling pressure while caval
  compression and critical closing pressure still reduce venous return.

### Pulmonary transit

- A 160 mL pressureless pathway in eight serial mixing stages gives a fixed
  2.0 s mean transport time.
- It delays flow from the RV to the LV while pressure gradients remain
  immediate.
- The direct pulmonary venous piston remains separate and can act before the
  delayed RV effect arrives.
- The mean time does not adapt to cardiac output, PVR or disease.

### Recruitment and ARDS

- `collapsed` describes how much lung is closed.
- `clung` describes tissue compliance if the whole lung were open.
- R/I describes recruitment relative to inflation during the reference PEEP
  manoeuvre. It is neither collapse nor a generic recruitability fraction.
- The 0.5 R/I division is a cohort-derived teaching threshold, not an
  outcome-proven treatment target.
- Hysteresis is optional; when enabled, opening and closing pressures differ,
  but recruitment remains instantaneous once a threshold is crossed.
- The prone implementation is deliberately heuristic and thought-generating.
  It combines recruitment, chest-wall and abdominal effects but cannot claim
  patient-specific prediction.

### COPD

- Loss of recoil is represented by high fully open lung compliance.
- Linear airway resistance and available expiratory time remain distinct.
- EFL adds one volume-dependent expiratory choke. Below the critical downstream
  pressure, more pressure cannot increase flow.
- Dynamic trapped volume is measured above passive equilibrium at the same PEEP,
  separating static emphysematous hyperinflation from breath-to-breath trapping.
- This is intentionally not a regional lung with heterogeneous time constants.

### Autonomic response

- One aggregate sympathetic state senses filtered systemic MAP.
- It affects heart rate, systemic resistance, stressed-volume recruitment and
  contractility together, with bounded gain and one 15 s time constant.
- It does not sense PVR, mPAP, RV distension, hypoxaemia or pulsatile arterial
  stretch directly.
- Clinical presets may encode compensation in their selected baseline heart
  rate, resistance and filling state. The model then generates only subsequent
  MAP-driven adjustment.

## 7. What must not be reintroduced without new evidence

- A diagnostic 13% PPV threshold.
- A modelled tidal-volume challenge with a claimed clinical cutoff.
- The Michard 2000 high-driving-pressure regression as a general calibration.
- A separate pulmonary obstruction-pressure state merely to reproduce Kenny's
  more precise analytical decomposition when it adds no distinct teaching
  outcome.
- A regional ARDS or COPD network without a specific teaching question and
  validating evidence.
- Multiple baroreflex, chemoreflex or autonomic arcs solely for realism.
- A PVR plot that hides either classical vascular limb or folds derecruitment
  into a competing third curve.
- A claim that equal tidal volume guarantees equal PVR or RV load.
- A claim that prone positioning, external PEEP in COPD or R/I identifies a
  universally optimal treatment.

## 9. Known limitations that belong in every future interpretation

The full wording is in `PHYSIOLOGY.md` and the README. The following list is the
minimum context for scenario work:

- no gas exchange, oxygen, CO₂, pH or shunt;
- HPV is a coefficient, not a response to calculated alveolar oxygen;
- no regional gravitational lung, local West-zone network or pulmonary
  vascular heterogeneity;
- no pressure/flow-dependent vascular recruitment and distension, viscosity,
  haematocrit, characteristic impedance or wave reflection;
- no coronary circulation, so systemic pressure does not directly restore RV
  coronary perfusion;
- no chemoreflex, vagal limb or differentiated autonomic efferent timing;
- no valvular disease, arrhythmia or bronchospasm heterogeneity;
- no regional COPD compartments, secretions, bronchodilator response,
  triggering or dyssynchrony;
- no recruitment time course; threshold crossing opens units immediately;
- pulmonary transit has fixed mean time and simplified dispersion;
- ejection fraction is approximately 5–10 percentage points pessimistic;
- Forward Euler remains the integrator, protected by flow floors and tested over
  the shipped range;
- validation is predominantly internal consistency, face validity, literature
  direction and selected human ranges, not experimental time-series fitting;
- there is no global sensitivity or identifiability analysis.

## 11. Next phase A — formal scenario verification

Create a new branch such as `codex/scenario-interpretability-audit`. Begin with
documentation and tests; do not retune equations simply because a scenario
description is uncomfortable.

### Deliverable

Add a canonical scenario-audit document, for example
`docs/SCENARIO_VALIDATION.md`. Give every preset the same structure:

1. **Teaching question** — one sentence stating why the preset exists.
2. **Encoded phenotype** — every parameter deliberately selected by the preset.
3. **Generated mechanism** — consequences that arise from equations rather than
   from preset values.
4. **Suggested manoeuvre** — the one or two controls a learner should change.
5. **Expected causal chain** — `input → mechanism → observable consequence`.
6. **Expected direction/range** — what should change, with conditions and a
   source where the literature supplies a number.
7. **Readouts that are interpretable** — measured, derived and internal
   coefficient clearly separated.
8. **Readouts to withhold or qualify** — including why.
9. **Absent clinical mechanisms** — omissions that materially constrain the
   scenario.
10. **Evidence** — primary literature or the most authoritative available
    source, with the exact population and measurement conditions.
11. **Executable check** — snapshot, monotone relation, bounded response or a
    deliberately documented non-monotone relation.
12. **Status** — verified, qualitatively plausible, deliberately heuristic or
    unresolved.

### Method

- Settle every baseline reproducibly before comparing it.
- Separate instantaneous respiratory-phase values from cycle means.
- Compare like with like: internal resistance coefficient against model
  coefficient, catheter-derived PVR against catheter-derived PVR.
- Reproduce the measurement conditions of a paper before importing its number.
- Prefer ranges and directional relations to invented exact targets.
- Where the physiology expects an optimum or J/U shape, test the shape rather
  than forcing monotonicity.
- Verify the proposed learner manoeuvre at low, reference and high settings.
- Test whether a result survives removal of the mechanism claimed to cause it.
- If several parameter combinations reproduce the same output, document the
  ambiguity instead of calling one causal interpretation proven.

### Recommended automated additions

- one contract asserting that every scenario has an audit entry;
- one explicit baseline-question contract per scenario;
- intervention checks for the manoeuvres named in scenario notes;
- checks that scenario text labels encoded compensation as encoded;
- checks that scenario documentation names its critical missing mechanisms;
- no hard-coded diagnostic threshold unless the model has been validated under
  the same conditions.

The first pass should be read-only with respect to equations. Produce findings,
then discuss any proposed model change before implementing it.

## 13. Next phase C — multi-page hypertextual manual

The manual should begin only after the scenario audit defines the claims it must
carry. A suitable implementation remains static and framework-free: shared CSS,
small vanilla JavaScript navigation helpers where useful, and ordinary pages
that work from the same static server as the app.

### Proposed information architecture

1. **Start here** — purpose, teaching-only warning, quick tour and first
   experiment.
2. **How to use the simulator** — transport, scenarios, controls, manoeuvres,
   plots, values disclosure and zoom.
3. **Conceptual model** — compartments, surrounding pressures, closed loop and
   why outputs emerge rather than being scripted.
4. **Respiratory mechanics** — Campbell diagram, modes, compliance, resistance,
   PEEP, auto-PEEP, EFL, recruitment and hysteresis.
5. **Venous return and filling** — stressed/unstressed volume, Pmsf, caval
   waterfall and the Guyton construction.
6. **Pulmonary circulation** — PVR limbs, J-curve, waterfall, open/closed beds,
   HPV, PVR coefficient versus derived PVR and transit.
7. **Cardiac interaction** — ventricular elastance, pericardium, septum, RV
   afterload, LV transmural afterload and pulmonary piston.
8. **Measurements and validity** — what is measured, derived or internal;
   PPV/SVV, wedge, R/I, stress index and hold-derived intercept.
9. **Scenario guide** — one hyperlinked page or section per audited scenario,
   with the standard structure from phase A.
10. **Model architecture and code** — modules, data flow, public API, integration
    and extension points.
11. **Evidence map** — claim-to-source table with population, conditions,
    measured quantity and current agreement status.
12. **Limitations** — global omissions followed by scenario-specific limits.
13. **Glossary and units** — clinical terms, model terms and conversions.
14. **Decision history** — curated links to model decisions, audits and
    postmortems rather than copying them wholesale.

### Documentation rules

- State whether every important quantity is a measurement, derived index,
  internal coefficient or selected parameter.
- Distinguish generated mechanisms from phenotype encoded by a preset.
- Put the validity conditions beside the number, not only in a global caveat.
- Use exact source conditions: species, ventilation, pressure/volume range,
  timing and method.
- Prefer primary literature for quantitative claims.
- Never turn a cohort median into an outcome-proven treatment threshold.
- Link equations to the code function that implements them and to the test that
  guards them.
- Use diagrams only where they clarify a relationship that prose cannot.
- Keep one canonical statement of each limitation and link to it.
- Include the explicit teaching-only warning on the start page and scenario
  pages.

### Preventing future drift

The manual must not become a second untested model. Where practical:

- import parameter labels/defaults and scenario metadata from the public model
  API rather than copying them;
- generate or verify numerical tables with deterministic scripts;
- add contracts that every scenario and user-facing parameter is documented;
- check internal links and source identifiers in CI;
- require a manual update when a model-decision entry changes a user-facing
  claim.

- each recommended learner manoeuvre has an executable directional check;
- clinically important absent mechanisms are visible per scenario;
