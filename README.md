# arthur

**ARTificial intelligence-built Heart–lUng Relationship model**

arthur is an interactive, browser-based teaching model of mechanical heart–lung interaction. It connects ventilation, respiratory mechanics, venous return, pulmonary vascular load, biventricular function and circulatory timing in one continuously running simulation.

The project is named in honour of Arthur Guyton and his contribution to the physiology of venous return and cardiac output.

> **Teaching only.** The model is a deliberately simplified physiological argument. It is not a patient-specific digital twin, a medical device or a treatment calculator, and must not be used to guide patient care.

For detailed physiology, implementation choices, figures, literature and limitations, use the **[web manual](manual/index.html)** or browse its **[Markdown home page](manual/home.md)**.

---

## Development provenance

The entire project—the physiological model, application code, tests, interface and manual—was generated by LLMs under human-in-the-loop direction, control and revision. **GPT-5.6-Sol with the high reasoning setting** was the principal model used to implement the physiology and write the manual. Other LLMs cross-reviewed internal consistency, physiological claims against the available literature, and agreement between the implemented model and its documentation.

Human review determined the teaching scope, supplied and selected literature, challenged modelling choices, tested the application and approved substantive changes. Literature used as scientific input is cited on the relevant manual pages and consolidated in the **[bibliography](manual/bibliography.md)**.

This development process is a provenance statement, not evidence of independent physiological or clinical validation. See **[Development provenance](manual/model-architecture.md#development-provenance)** and **[Validation](manual/validation.md#development-review-and-validation)**.

## Start in two minutes

The application is written in vanilla JavaScript and has no build step or runtime dependencies. ES modules must be served over HTTP rather than opened through `file://`.

```bash
npm run serve
```

Then open:

- application: <http://localhost:8422>
- manual: <http://localhost:8422/manual/>

For development, use the no-cache server:

```bash
npm run serve:dev
```

This serves the same project at <http://localhost:8499> while preventing stale ES modules during editing.

New users can begin with the manual's **[ten-minute guided exploration](manual/quick-start.md)**. The **[conventions](manual/conventions.md)** explain units, badges and reading rules.

## What the project is designed to teach

The model is intended for mechanistic questions such as:

- Why does positive-pressure inspiration commonly reduce venous return while spontaneous inspiration can increase right-heart filling?
- Why can measured CVP rise while transmural filling pressure falls?
- How do PEEP, lung volume, recruitment and expiratory trapping alter right-ventricular load?
- Why can positive intrathoracic pressure reduce left-ventricular transmural afterload?
- How do stressed volume, venous tone and resistance to venous return affect the Guyton operating point?
- Why does a change in RV output reach the LV only after pulmonary transit?
- How do ventricular interdependence and pericardial constraint couple the two sides of the heart?

The best use is comparative: change one input, allow the circulation to settle, and follow the causal chain across pressure, flow, volume and ventricular response. See **[The four effects of a breath](manual/the-four-effects-of-a-breath.md)** for the central physiological map.

## Model overview

### Respiratory mechanics

The respiratory system combines the lung and chest wall with airway resistance and patient effort. It supports spontaneous breathing, volume control, pressure control and pressure support.

The lung model includes:

- a pressure–volume relation with independent **aerated-lung compliance** and **maximum lung capacity**;
- already aerated, collapsed, recruitable and non-recruitable tissue;
- a bedside-inspired recruitment-to-inflation ratio;
- optional recruitment hysteresis with separate opening and closing ranges;
- expiratory flow limitation and dynamic hyperinflation;
- chest-wall and abdominal pressure transmission;
- a deliberately coarse prone-position transformation.

Detailed pages: **[Equation of motion](manual/equation-of-motion.md)**, **[Pressure–volume curve](manual/pressure-volume-curve.md)**, **[Two-population lung](manual/two-population-lung.md)**, **[Recruitment and R/I](manual/recruitment-and-ri.md)**, **[Hysteresis](manual/hysteresis.md)** and **[Expiratory flow limitation](manual/expiratory-flow-limitation.md)**.

### Closed-loop circulation

Blood volume is conserved across systemic venous and arterial reservoirs, four cardiac chambers and the pulmonary circulation. Chamber pressures are referenced to the pressures surrounding them, allowing measured and transmural pressures to diverge.

The cardiovascular model includes:

- time-varying ventricular elastance;
- preload-, contractility- and afterload-dependent ejection;
- stressed and unstressed systemic venous volume;
- venous tone, venous compliance and resistance to venous return as separate mechanisms;
- systemic vascular resistance;
- ventricular septal interaction and shared pericardial constraint;
- a bounded aggregate baroreflex acting on heart rate, vascular tone, resistance and contractility.

Detailed pages: **[Venous return](manual/venous-return.md)**, **[Stressed volume](manual/stressed-volume.md)**, **[Venous tone](manual/venous-tone.md)**, **[The right ventricle](manual/the-right-ventricle.md)**, **[Ventricular interdependence](manual/ventricular-interdependence.md)** and **[Baroreflex](manual/baroreflex.md)**.

### Pulmonary circulation and heart–lung coupling

Pulmonary vascular resistance changes with lung volume through opposing alveolar and extra-alveolar components. Open and derecruited regions form aggregate parallel vascular pathways, with optional hypoxic vasoconstriction in the derecruited pathway.

The model also represents:

- the classical J-shaped relationship between PVR and lung volume;
- aggregate West-zone and vascular-waterfall behaviour;
- distinct internal resistance and catheter-derived PVR readouts;
- lung inflation displacing pulmonary blood toward the left atrium;
- state-dependent pulmonary transit based on represented central blood volume and RV output;
- delayed serial coupling between RV and LV output.

Detailed pages: **[Pulmonary vascular resistance](manual/pulmonary-vascular-resistance.md)**, **[Vascular waterfalls](manual/vascular-waterfalls.md)**, **[Hypoxic vasoconstriction](manual/hypoxic-vasoconstriction.md)** and **[Pulmonary transit](manual/pulmonary-transit.md)**.

### Measurements and bedside concepts

The interface reports pressures, flows, chamber volumes and derived physiological indices. Named bedside quantities are displayed only within the limits of what the model can represent.

These include:

- measured and transmural CVP;
- cardiac output, stroke volume and ventricular volumes;
- airway, alveolar, pleural and abdominal pressures;
- total PEEP, intrinsic PEEP and trapped volume;
- plateau pressure, driving pressure and respiratory compliance;
- mPAP, wedge surrogate, resistance coefficient and derived PVR;
- stress index, pulse pressure variation and stroke volume variation;
- mean systemic filling pressure and model preload reserve;
- open fraction, R/I and pulmonary transit estimates.

Values can be marked *caution* or withheld as *unavailable* when their assumptions are absent. See **[Numerical tiles](manual/numeric-tiles.md)** and **[Interpretability](manual/interpretability.md)**.

End-expiratory and end-inspiratory holds can also generate measured pressure–flow points for an occlusion-based Guyton construction. See **[Manoeuvres](manual/manoeuvres.md)** and **[Pmsf and occlusions](manual/pmsf-and-occlusions.md)**.

| panel | purpose | manual |

## Clinical scenarios

Scenarios are starting phenotypes built around one teaching question. They are not complete disease simulations, and changing any control after loading one creates a custom state.

| scenario | central question |
|---|---|
| Healthy, breathing spontaneously | Why can CVP fall while right-heart filling increases? |
| Healthy, passive volume control | What changes when the sign of inspiratory pressure reverses? |
| PEEP escalation | How do venous return, lung volume and RV load change together? |
| Septic shock, fluid responsive | How can compensation conceal low effective filling? |
| Large pleural swings, limited preload reserve | Why is a pressure swing not equivalent to fluid responsiveness? |
| ARDS with right ventricular failure | How does recruitability alter the haemodynamic cost of PEEP? |
| Acute pulmonary embolism | How does aggregate pulmonary vascular load affect a vulnerable RV? |
| Cardiogenic pulmonary oedema | When can reduced LV transmural afterload outweigh lost preload? |
| Stiff chest wall | Why does the same tidal volume transmit more pleural pressure? |
| COPD with dynamic hyperinflation | How do expiratory time, flow limitation and external PEEP interact? |
| Intra-abdominal hypertension | How can abdominal pressure both mobilise and obstruct venous return? |

The **[scenario manual page](manual/scenarios.md)** explains how to interrogate each phenotype. **[Scenario validation](docs/SCENARIO_VALIDATION.md)** records whether the current implementation demonstrates its intended lesson and which conclusions remain qualified.

## Validation and tests

The dependency-free test suite covers:

- blood-volume conservation and compartment positivity;
- deterministic behaviour and time-step refinement;
- a reproducible control-space safety sweep;
- directional physiological relationships;
- recruitment, hysteresis, stress index, EFL and pulmonary transit;
- scenario-specific teaching mechanisms and settled snapshots;
- agreement between the integrator, public model API and plotted curves;
- executable literature constraints;
- numerical examples generated directly from the current model;
- manual completeness, links and Markdown structure.

Run the checks with:

```bash
npm test
npm run manual:build
npm run manual:lint
```

Snapshot regeneration is intentionally separate:

```bash
npm run snapshots
```

A changed snapshot is a model change that requires review, not an automatic test repair. A green suite demonstrates numerical and mechanistic contracts; it does not establish patient-level quantitative validation. See **[Validation](manual/validation.md)**.

## Architecture

The project deliberately remains framework-free:

- vanilla JavaScript ES modules;
- HTML, CSS, canvas and SVG;
- no application build step;
- no frontend or simulation framework;
- one public model boundary in `src/model/index.js`;
- controls generated from `src/model/parameters.js`;
- scenarios defined in `src/model/scenarios.js`;
- Markdown manual rendered locally with bundled dependencies.

```text
index.html                 application shell
styles/                    application styling
src/main.js                transport, scenarios and render loop
src/model/                 respiratory, circulatory and regulatory model
src/ui/                    controls, readouts and six panels
manual/                    web manual, figures and documentation tooling
docs/                      audits, literature constraints and decision records
tests/                     dependency-free verification suite
tools/serve.mjs            no-cache development server
```

For the dependency direction, integration loop and state layout, see **[Model architecture](manual/model-architecture.md)**.

## Programmatic use

The page exposes a small browser handle for teaching scripts and experiments:

```js
heartLung.sim.setParam('peep', 12);
heartLung.step(20);          // advance model time and repaint
heartLung.sim.metrics;       // current derived measurements
heartLung.sim.applyScenario(scenario);
```

The UI imports the model only through `src/model/index.js`; the public boundary is checked by the test suite.

## Important limits

The model does **not** include:

- oxygen, carbon dioxide, pH, shunt or gas exchange;
- regional lung mechanics, ventilation–perfusion matching or pendelluft;
- a regional pulmonary vascular tree or complete pulsatile RV afterload;
- explicit clot burden, blood viscosity or chronic vascular remodelling;
- coronary circulation, myocardial ischaemia, valves or arrhythmias;
- renal, endocrine, inflammatory or long-term fluid physiology;
- drug dosing, outcome prediction or patient-specific parameter estimation;
- a validated fluid-responsiveness threshold or tidal-volume challenge;
- a clinically adequate model of weaning failure or cardiac tamponade.

Several controls are aggregate teaching coefficients rather than measurable patient parameters. Named clinical indices may be simplified, qualified or unavailable. Every scenario inherits these omissions.

Read **[Global limits](manual/global-limits.md)** and **[Interpretability](manual/interpretability.md)** before drawing conclusions from absolute values.
